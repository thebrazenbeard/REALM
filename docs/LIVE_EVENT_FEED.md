# Opt-in authenticated near-real-time feed (source preview)

REALM is a **Real-Time Evolving Sandbox**. The prototype gateway already writes
world events to its SQLite event log, with UTC `at` timestamps and increasing
database IDs. This addition gives a connected player a bounded long-poll feed
without requiring a full refresh every fixed interval.

**State:** source only; no service is installed or deployed on Lappy/VN2.
This is **not** SSE, WebSocket, a public gameplay API, or an always-running
world simulation. The world evolves only when a host/game action writes events.

## Opt in

The host can replace the ordinary loopback `GatewayServer` with:

```python
from realm.gateway import Gateway
from realm.event_stream import FeedWaitServer

gateway = Gateway('world.sqlite3', world_id='demo')
server = FeedWaitServer(gateway, ('http://127.0.0.1:8000',), port=8768)
try:
    server.serve_forever()
finally:
    server.server_close()
```

Host-provisioned **player bearer credentials** are required, as with the existing
gateway. Call `server.shutdown()` before `server.server_close()` when stopping
an active service from another thread.

## Wire contract

`GET /api/v1/feed/wait?after=<cursor>&wait_ms=<milliseconds>`

- Header: `Authorization: Bearer <host-issued-player-token>`
- Optional `player` must match the authenticated player. It never selects the
  principal. No world name can be selected via request parameters.
- `after` defaults to 0; nonnegative 64-bit signed integer.
- `wait_ms` defaults to 1000; valid 0 through 5000 (5-second server cap).
- Response is the same `{ok, events, cursor}` shape as `GET /api/v1/feed`.
  IDs are monotonically increasing within one SQLite world. The `at` event
  timestamp is generated by the engine in UTC.
- On event arrival return immediately; on timeout return HTTP 200 with
  `events: []` and unchanged `cursor`. Reconnect with that cursor.
- On bearer revocation/rotation while waiting, HTTP 401; stop returns 503.
  Invalid params return 400; occupied waiter slots return 429.
- The request is read-only. Per-request reads are bounded by the base gateway's
  100-event cap; semaphore slots are capped at 32, default 8.

**Scope:** only the authenticated player's current room in the world's bound
SQLite DB, as enforced by the current `Gateway.feed`. Room movement changes
what the player is allowed to read. This is not historical audience-grant replay;
do not treat prior room occupancy or cursor possession as a private authorization.
The existing v1 gateway provides no token expiry, public HTTPS/TLS, anti-abuse
identity registration, or historical per-recipient delivery ledger. The endpoint
inherits those limits and therefore remains for trusted **localhost** use only.
Never expose it directly to the public Internet.

## Client retry

Keep one outstanding long-poll at a time; do not include bearer tokens in URLs
or logs. Receive an event batch, process ascending IDs, persist the last
processed cursor, then start another request. If a response is lost, retry with
the last processed cursor; duplicates are possible and must be deduplicated by
world ID and event ID. Always verify a reconnect is to the same host world;
worlds do not share event-ID namespaces.
